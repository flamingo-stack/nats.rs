Regression and integration tests verifying that NATS connections, subscriptions, and JetStream consumers flush and close cleanly within acceptable time bounds when dropped or explicitly closed.

## Key Components

| Test | Description |
|---|---|
| `drop_flushes` | Verifies that dropping a `Connection` triggers an implicit flush, delivering any pending published messages |
| `two_connections` | Confirms cloned connections remain usable after one clone is dropped |
| `async_subscription_drop` | Ensures async subscriptions are properly closed on drop, preventing thread pool exhaustion after 600 iterations |
| `shutdown_responsiveness_regression_check` | Asserts `conn.close()` completes within 5 seconds |
| `drop_responsiveness_regression_check` | Asserts implicit drop of a connection completes within 5 seconds |
| `close_responsiveness_regression_jetstream` | Validates timely `nc.close()` with an active JetStream push subscriber and process handler |
| `close_responsiveness_regression_jetstream_complex` | Tests shutdown with multi-subject streams, concurrent publishing, and a `crossbeam_channel` process handler |
| `run_basic_jetstream` | Helper that starts a JetStream-enabled server and returns `(Server, Connection, JetStream)` |

## Usage Example

```rust
// Reproduce the drop-flushes guarantee in your own code:
let nc = nats::connect("nats://127.0.0.1:4222")?;
let sub = nc.subscribe("inbox.123")?;

nc.publish("inbox.123", b"hello")?;
drop(nc); // implicit flush — message is guaranteed to be sent

let msg = sub.next().unwrap();
assert_eq!(msg.data, b"hello");

// Use run_basic_jetstream() in other tests requiring JetStream:
let (_s, conn, js) = run_basic_jetstream();
js.add_stream(nats::jetstream::StreamConfig {
    name: "MY_STREAM".to_string(),
    subjects: vec!["events".to_string()],
    ..Default::default()
})?;
conn.close();
```

## Notes

- All tests require a running `nats_server` instance spun up via `nats_server::run_basic_server()` or `run_server("tests/configs/jetstream.conf")`.
- The 5-second deadline in responsiveness checks guards against regressions where shutdown could block indefinitely on pending I/O or thread-pool tasks.
- Source: [`tests/drop.rs`](https://github.com/flamingo-stack/nats.rs/blob/main/tests/drop.rs)
