Async error handling integration tests that verify permission violation callbacks are correctly triggered when a NATS client attempts unauthorized publish or subscribe operations.

## Key Components

- **`pub_perms`** — Test asserting that publishing to a restricted subject (`"foo"`) fires the error callback with a `Permissions Violation for Publish` message, without causing a disconnect.
- **`sub_perms`** — Test asserting that subscribing to a restricted subject fires the error callback with a `Permissions Violation for Subscription` message, without causing a disconnect.

Both tests use `crossbeam_channel::bounded` channels to capture asynchronous error and disconnect callbacks in a synchronous test context.

## Usage Example

```rust
use crossbeam_channel::bounded;
use std::time::Duration;

let (etx, erx) = bounded(1);
let (dtx, drx) = bounded(1);

let nc = nats::Options::with_user_pass("derek", "s3cr3t!")
    .error_callback(move |err| etx.send(err).unwrap())
    .disconnect_callback(move || { let _ = dtx.send(true); })
    .connect("nats://localhost:4222")
    .expect("could not connect");

nc.publish("restricted-subject", "data").unwrap();

// Expect a permissions error, not a disconnect
let err = erx.recv_timeout(Duration::from_millis(100));
assert!(err.is_ok());
assert!(drx.recv_timeout(Duration::from_millis(100)).is_err());
```

## Notes

- Tests require a running NATS server configured with `tests/configs/perms.conf` defining subject-level publish/subscribe restrictions for the `derek` user.
- The `drx.recv_timeout(...).is_err()` assertion confirms the client remains connected after a permission violation — the server sends an error but does not disconnect.
