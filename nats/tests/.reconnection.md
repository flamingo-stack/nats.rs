Reconnection stress test validating NATS client behavior over an intentionally faulty server connection. The test verifies that request/reply messaging succeeds reliably despite repeated connection interruptions.

## Key Components

| Item | Description |
|------|-------------|
| `reconnect_test` | Integration test (marked `#[ignore]`) that exercises reconnection logic using a bugginess-injected `NatsTestServer` |
| `NatsTestServer` | Test server built with `bugginess(200)` to simulate unstable connections |
| Watchdog thread | Background thread that force-kills the process after 15 minutes if the test never completes |
| `tx` thread | Publisher/requester thread that sends `request_timeout` calls until 25 successful replies are received |
| `subscriber` loop | Main thread subscriber that replies to each inbound message to close the request/reply cycle |

## Usage Example

This test is excluded from normal test runs via `#[ignore]`. Run it explicitly:

```bash
cargo test reconnect_test -- --ignored --nocapture
```

The test flow:

```rust
// Server starts with artificial instability (bugginess = 200)
let server = NatsTestServer::build().bugginess(200).spawn();

// Client connects with unlimited reconnect attempts
let nc = nats::Options::new()
    .max_reconnects(None)
    .connect(server.address().to_string())?;

// Requester sends up to 25 successful request/reply pairs
// despite intermittent timeouts and reconnections
nc.request_timeout(
    "rust.tests.faulty_requests",
    "Help me?",
    Duration::from_millis(200),
)?;
```

The test passes only when exactly 25 successful round-trips complete before the 15-minute watchdog fires.

> **Note:** Requires the `nats_test_server` dev-dependency. See the full source at [`tests/reconnection.rs`](https://github.com/flamingo-stack/nats.rs/blob/main/tests/reconnection.rs).
