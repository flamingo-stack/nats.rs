Drain functionality integration test for the NATS Rust client, verifying that subscriptions correctly process all in-flight messages before closing.

## Key Components

- **`drain()`** — Integration test that validates the complete drain lifecycle for a NATS subscription.

## Test Behavior

The test covers three scenarios:

1. **Buffered message delivery** — Publishes 10,000 messages to a subject, calls `sub.drain()`, then iterates via `sub.iter()` to confirm all 10,000 messages are received before the subscription closes.
2. **Post-drain publish rejection** — Verifies that messages published to an already-drained subscription are not delivered (`sub.next()` returns `None`).
3. **Explicit unsubscribe** — Confirms that `sub.unsubscribe()` succeeds cleanly after draining.

## Usage Example

```rust
// Connect and subscribe
let nc = nats::connect("nats://localhost:4222").unwrap();
let sub = nc.subscribe("test").unwrap();

// Publish messages
for _ in 0..10000 {
    nc.publish("test", b"foo").unwrap();
}

// Drain: signal no new messages, then consume remaining
sub.drain().unwrap();
let count = sub.iter().count();
assert_eq!(10000, count);

// Post-drain: no further messages are delivered
nc.publish("test", b"more").unwrap();
assert!(sub.next().is_none());

sub.unsubscribe().unwrap();
```
