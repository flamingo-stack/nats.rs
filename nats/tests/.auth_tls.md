TLS authentication integration tests for NATS client connections, validating certificate-based mutual TLS (mTLS) handshakes and failure scenarios.

## Key Components

| Test | Description |
|------|-------------|
| `basic_tls` | Verifies TLS connections with username/password + client certificates, including failure cases and a combined PEM file scenario |
| `ip_basic_tls` | Verifies TLS connections using an IP-based SAN certificate against a `127.0.0.1` endpoint |

## Usage Example

```rust
// Connect with separate CA root, client cert, and key files
let path = PathBuf::from(env!("CARGO_MANIFEST_DIR"));

nats::Options::with_user_pass("derek", "porkchop")
    .add_root_certificate(path.join("tests/configs/certs/rootCA.pem"))
    .client_cert(
        path.join("tests/configs/certs/client-cert.pem"),
        path.join("tests/configs/certs/client-key.pem"),
    )
    .connect("tls://your-nats-server:4222")
    .unwrap();

// Connect using a single combined PEM (root CA + client cert + key)
nats::Options::with_user_pass("derek", "porkchop")
    .add_root_certificate(path.join("tests/configs/certs/client-all.pem"))
    .client_cert(
        path.join("tests/configs/certs/client-all.pem"),
        path.join("tests/configs/certs/client-all.pem"),
    )
    .connect("tls://your-nats-server:4222")
    .unwrap();
```

**Failure cases covered:**
- Connecting without any certificates → expected error
- Connecting via raw IP when the certificate lacks a matching SAN entry → expected error

## Notes

- Test configs and certificates live under `tests/configs/certs/`
- IP-based TLS requires a certificate with a proper IP SAN (see `ip-ca.pem` / `ip-tls.conf`)
- Source: [`tests/auth_tls.rs`](https://github.com/flamingo-stack/nats.rs/blob/main/tests/auth_tls.rs)
