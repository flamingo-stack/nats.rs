Token-based authentication integration test for NATS connections, verifying that unauthenticated connections are rejected and that valid tokens are accepted via both `Options::with_token` and URL-embedded token methods.

## Key Components

- **`token_auth` test** — End-to-end test that spins up a NATS server with token authentication enabled (`tests/configs/token_auth.conf`) and asserts four authentication scenarios.

## Test Scenarios

| Scenario | Expected Result |
|---|---|
| No token provided | Connection rejected (`Err`) |
| Valid token via `Options::with_token` | Connection accepted (`Ok`) |
| Valid token embedded in client URL | Connection accepted (`Ok`) |
| URL token overrides `Options` bad token | Connection accepted (`Ok`) |

## Usage Example

```rust
// Connect using Options::with_token
let conn = nats::Options::with_token("my-secret-token")
    .connect("nats://localhost:4222")
    .expect("Failed to connect");

// Connect using a token embedded in the URL
let conn = nats::connect("nats://my-secret-token@localhost:4222")
    .expect("Failed to connect");
```

## Notes

- The server config at `tests/configs/token_auth.conf` must define the expected token (`some-auth-token`).
- When a token is present in both `Options::with_token` and the URL, the **URL token takes precedence**, allowing override of a bad or missing `Options` token.
