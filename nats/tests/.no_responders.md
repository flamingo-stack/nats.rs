Demonstrates the NATS "no responders" feature, verifying that a request to a subject with no active subscribers returns a "no responders" error.

## Key Components

- **`no_responders` test** — Integration test that confirms the client panics with `"no responders"` when calling `request()` on a subject that has no subscribers.

## Usage Example

```rust
#[test]
#[should_panic(expected = "no responders")]
fn no_responders() {
    let s = nats_server::run_basic_server();
    let nc = nats::connect(s.client_url()).expect("could not connect");
    // No subscriber on "nobody-home" — triggers "no responders" error
    nc.request("nobody-home", "hello").unwrap();
}
```

## Notes

- Relies on `nats_server::run_basic_server()` to spin up a local NATS server for the test.
- The `#[should_panic]` attribute asserts the expected error message, validating that the client correctly surfaces the NATS 2.2+ no-responders protocol signal rather than hanging indefinitely.
