Brief description of the file's purpose in 1-2 sentences.

This file implements a NATS test server (`NatsTestServer`) for use in integration tests and CI environments. It simulates a real NATS broker over TCP, supporting pub/sub routing, ping/pong keepalives, client subscription management, and injectable failure modes for resilience testing.

## Key Components

| Component | Description |
|---|---|
| `NatsTestServer` | Main server struct; binds a TCP listener, manages lifecycle via `Drop`, exposes the bound `SocketAddr` |
| `NatsTestServerBuilder<A>` | Builder for configuring and spawning the server (address, bugginess probability, port hopping) |
| `ConnectInfo` | Serializable struct for the NATS `CONNECT` message payload (auth, TLS, echo, lang/version) |
| `Client` | Internal per-connection state (subscriptions, ping tracking, socket handle) |
| `read_line` | Reads a single CRLF-terminated line from a `TcpStream` |
| `subject_matches` | Routes published subjects to matching subscriber IDs (not shown in excerpt) |
| `ClientAction` | Enum of server-side outcomes per command (`None`, `Evict`, `HopPorts`, `Publish`) |

## Usage Example

```rust
use nats_test_server::NatsTestServer;

// Start a basic test server on an OS-assigned port
let server = NatsTestServer::build().spawn();
let addr = server.address(); // e.g. "127.0.0.1:54321"

// Connect your NATS client to addr, run tests...

// Server stops automatically when `server` is dropped

// Start a server with simulated failures (1-in-50 chance per loop)
let buggy_server = NatsTestServer::build()
    .bugginess(50)
    .hop_ports(true)
    .spawn();

// Restart the server on the same port
let restarted = buggy_server.restart().spawn();
```
