Represents a NATS message received on a subject, providing methods for responding, acknowledging JetStream messages, and inspecting message metadata.

## Key Components

- **`Message`** — Core struct with fields: `subject`, `reply`, `data`, `headers`, `client`, and `double_acked`
- **`Message::new()`** — Constructs a clientless `Message` for data passing or testing
- **`respond()`** — Publishes a reply to the message's reply subject
- **`ack()` / `ack_kind()`** — Acknowledge a JetStream message (fire-and-forget)
- **`double_ack()`** — Acknowledge a JetStream message and retry until the server confirms receipt
- **`jetstream_message_info()`** — Parses the JetStream reply subject into a `JetStreamMessageInfo` struct
- **`is_no_responders()`** — Detects `503` status (no subscribers available)
- **`is_flow_control()` / `is_idle_heartbeat()`** — Internal helpers for JetStream flow control detection

## Usage Example

```rust
use nats::Message;

// Create a standalone message (no client binding)
let msg = Message::new("my.subject", Some("inbox.reply"), b"hello", None);

// Respond to a request/reply message
msg.respond(b"pong")?;

// Acknowledge a JetStream message
msg.ack()?;

// Double-ack with a specific acknowledgment kind
msg.double_ack(nats::jetstream::AckKind::Ack)?;

// Check if it's a no-responders error
if msg.is_no_responders() {
    eprintln!("No subscribers found for subject");
}

// Inspect JetStream metadata
if let Some(info) = msg.jetstream_message_info() {
    println!("Stream: {}, Seq: {}", info.stream, info.stream_seq);
}
```

> **Note:** Most methods (e.g., `respond`, `ack`, `double_ack`) require a bound `Client`. Messages created via `Message::new()` without a client will return `io::ErrorKind::NotConnected` errors on those calls.
