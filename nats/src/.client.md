Manages the core NATS client state, connection lifecycle, and background thread coordination for reading/writing messages and maintaining server connectivity.

## Key Components

- **`Client`** – The main cloneable client struct holding shared `Arc`-wrapped state, server info, shutdown flag, and handles to background threads.
- **`State`** – Shared mutable state split across three `Mutex`-guarded sub-structs: `WriteState`, `ReadState`, and `MetaState`.
- **`WriteState`** – Holds the buffered writer, reconnect buffer, flush channel sender, and next subscription ID.
- **`ReadState`** – Tracks active subscriptions, pending PONG channels, last server activity timestamp, and outstanding PINGs.
- **`Subscription`** – Represents a registered subscription with subject, optional queue group, message sender channel, preprocessor, and message limits.
- **`Preprocessor`** – A type alias for a boxed predicate `Fn(u64, &Message) -> bool` run on incoming messages before delivery.
- **`Client::connect`** – Initializes the client, spawns a client thread (handles reconnection and message dispatch) and a flush thread (periodic buffer flushing and PING/PONG keepalive).
- **`Client::flush`** – Sends a PING and waits for a PONG to confirm buffered messages reached the server.

## Usage Example

```rust
use nats::Options;

// Connect is called internally; typical usage goes through the public API:
let nc = nats::connect("nats://localhost:4222")?;

// Ensure buffered publishes are flushed to the server
nc.flush()?;

// Retrieve current server info
let info = nc.server_info();
println!("Connected to NATS server v{}", info.version);
```

## Notes

- **Locking protocol**: `write` lock must always be acquired before `read` lock to avoid deadlocks.
- The flush thread enforces a minimum 5ms interval between flushes and sends PINGs every 2 minutes, disconnecting after 2 unanswered PINGs.
