Provides the `PullSubscription` type for JetStream pull-based consumers in NATS, enabling client-initiated message retrieval with blocking, non-blocking, and timeout-based fetch strategies.

## Key Components

- **`PullSubscription`** — Clonable, `Arc`-backed struct representing a pull consumer subscription. Wraps an `Inner` containing the channel receiver, inbox, consumer metadata, and JetStream context.
- **`Inner`** — Private struct holding subscription state; implements `Drop` to automatically unsubscribe and optionally delete the consumer.
- **`fetch(batch)`** — Returns a blocking `BatchIter` that retrieves exactly `batch` messages.
- **`timeout_fetch(batch, timeout)`** — Returns a `TimeoutBatchIter` that stops when the batch is exhausted or the timeout elapses.
- **`fetch_with_handler(batch, handler)`** — High-level method that fetches messages and applies a closure, auto-acking per the consumer's `AckPolicy`.
- **`next()`** / **`try_next()`** / **`next_timeout(duration)`** — Low-level primitives for single-message retrieval (blocking, non-blocking, and timeout-bounded respectively). Require a prior `request_batch` call.
- **`request_batch(options)`** — Sends a pull request to the server for a given batch size/options.

## Usage Example

```rust
use nats::jetstream::BatchOptions;
use std::time::Duration;

fn main() -> std::io::Result<()> {
    let client = nats::connect("demo.nats.io")?;
    let context = nats::jetstream::new(client);

    context.add_stream("orders")?;
    context.publish("orders", "order-1")?;

    let consumer = context.pull_subscribe("orders")?;

    // Blocking fetch of 5 messages
    for msg in consumer.fetch(5)? {
        println!("Got: {:?}", msg);
    }

    // Fetch with timeout
    for msg in consumer.timeout_fetch(5, Duration::from_millis(500))? {
        println!("Got: {:?}", msg);
    }

    // Fetch with auto-ack handler
    consumer.fetch_with_handler(10, |msg| {
        println!("Processing: {:?}", msg);
        Ok(())
    })?;

    Ok(())
}
```

> **Note:** `next()`, `try_next()`, and `next_timeout()` are low-level primitives requiring an explicit `consumer.request_batch(n)?` call before use. Prefer `fetch` or `fetch_with_handler` for most use cases.
