Provides NATS JetStream Object Store support for storing and retrieving large binary objects (blobs) in streams, with chunked upload/download, SHA-256 integrity verification, and bucket lifecycle management.

## Key Components

| Item | Type | Description |
|------|------|-------------|
| `Config` | Struct | Bucket configuration: name, description, max age, storage type, replicas |
| `ObjectStore` | Struct | Primary handle for interacting with a named object store bucket |
| `Object` | Struct | Represents a retrieved object; implements `io::Read` for streaming reads |
| `ObjectInfo` | Struct | Full metadata for a stored object (name, size, chunks, digest, timestamps) |
| `ObjectMeta` | Struct | Lightweight metadata subset (name, description, link) |
| `ObjectLink` | Struct | Reference to another object, optionally in a different bucket |
| `JetStream::create_object_store` | Method | Creates a new bucket backed by a JetStream stream |
| `JetStream::object_store` | Method | Binds to an existing bucket |
| `JetStream::delete_object_store` | Method | Deletes the underlying stream for a bucket |

## Usage Example

```rust
use nats::object_store::Config;

fn main() -> std::io::Result<()> {
    let client = nats::connect("demo.nats.io")?;
    let context = nats::jetstream::new(client);

    // Create a bucket
    let bucket = context.create_object_store(&Config {
        bucket: "my-bucket".to_string(),
        max_age: std::time::Duration::from_secs(3600),
        num_replicas: 1,
        ..Default::default()
    })?;

    // Store an object
    let data = b"hello world";
    let info = bucket.put("my-object", &mut data.as_ref())?;
    println!("Stored {} bytes in {} chunks", info.size, info.chunks);

    // Retrieve and read an object (implements io::Read)
    let mut object = bucket.get("my-object")?;
    let mut buf = Vec::new();
    std::io::Read::read_to_end(&mut object, &mut buf)?;

    // Cleanup
    context.delete_object_store("my-bucket")?;
    Ok(())
}
```

## Notes

- Requires NATS server **≥ 2.6.2**
- Objects are chunked at **128 KiB** by default
- Downloads validate a **SHA-256 digest** automatically; returns `ErrorKind::InvalidData` on mismatch
- Bucket names: alphanumeric, `_`, `-` only; object names allow `/`, `.`, `=` in addition
- Stream naming convention: `OBJ_<bucket>` with subjects `$O.<bucket>.C.>` (chunks) and `$O.<bucket>.M.>` (metadata)
