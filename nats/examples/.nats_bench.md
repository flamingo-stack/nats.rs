A CLI benchmarking tool for measuring NATS message publishing and subscribing throughput and latency using concurrent threads.

## Key Components

| Component | Description |
|-----------|-------------|
| `Args` | `StructOpt`-derived CLI argument parser for configuring server URL, credentials, message size, publisher/subscriber counts, and TLS |
| `HISTOGRAM` | Global `Histo` instance (via `lazy_static`) for recording per-publish latency in nanoseconds |
| `connect` closure | Factory that builds a `nats::Options` connection with optional credentials and TLS |
| Publisher threads | Spawn one thread per publisher; each publishes `messages / pubs` fixed-size messages and records latency |
| Subscriber threads | Spawn one thread per subscriber; each drains the expected message count from a subject subscription |
| `Barrier` | Synchronizes all publisher, subscriber, and main threads so measurement starts only when all are ready |

## Usage Example

```bash
# Basic publish benchmark: 100k messages, 128 bytes, 4 publishers
nats_bench --publishers 4 --number-of-messages 100000 --message-size 128 my.subject

# With subscribers and credentials
nats_bench -p 2 -s 2 --creds /path/to/user.creds -n 50000 my.subject

# Against a remote TLS server
nats_bench --url nats://broker.example.com:4222 -tls my.subject
```

**Sample output:**

```text
Starting benchmark [msgs=100000, msgsize=128, pubs=4, subs=0]
duration: 1.243s frequency: 80450 mbps: 10
publish latency breakdown in nanoseconds:
                min:       4200 ns
     50th percentile:       6800 ns
     99th percentile:      18500 ns
                max:     142000 ns
```

> **Note:** Message count is automatically rounded up to the nearest multiple of the publisher count to ensure even distribution across threads.
