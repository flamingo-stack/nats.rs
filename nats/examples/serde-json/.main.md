Demonstrates publishing and receiving a JSON-serialized struct over NATS using a self-subscription pattern on a unique inbox subject.

## Key Components

- **`Person`** — A serializable/deserializable struct (`Serialize`, `Deserialize`, `Debug`) representing a simple data model with `first_name`, `last_name`, and `age` fields.
- **`main()`** — Entry point that connects to NATS, publishes a `Person` as JSON to an inbox subject, then receives and deserializes it from the subscription.

## Usage Example

```rust
use serde::{Deserialize, Serialize};

#[derive(Serialize, Deserialize, Debug)]
struct Person {
    first_name: String,
    last_name: String,
    age: u8,
}

fn main() -> std::io::Result<()> {
    // Connect to the public NATS demo server
    let nc = nats::connect("demo.nats.io")?;

    // Generate a unique inbox subject
    let subj = nc.new_inbox();

    let p = Person {
        first_name: "derek".to_owned(),
        last_name: "collison".to_owned(),
        age: 22,
    };

    // Subscribe before publishing to avoid missing the message
    let sub = nc.subscribe(&subj)?;

    // Publish the struct serialized as JSON bytes
    nc.publish(&subj, serde_json::to_vec(&p)?)?;

    // Deserialize the first received message back into a Person
    let mut msgs = sub.iter().map(|msg| {
        serde_json::from_slice::<Person>(&msg.data).unwrap()
    });

    println!("received {:?}", msgs.next().unwrap());
    Ok(())
}
```

## Notes

- `nc.new_inbox()` generates a unique `_INBOX.<nonce>` subject, avoiding collisions with other publishers.
- The subscription is created **before** publishing to guarantee the message is not missed.
- `sub.iter()` blocks until a message arrives, making this a synchronous receive pattern.
