Benchmark suite for measuring NATS publish throughput using the [Criterion](https://github.com/bheisler/criterion.rs) benchmarking framework.

## Key Components

- **`pub_benchmark`** — Criterion benchmark function that measures publish performance across multiple message sizes (`32`, `128`, `256`, `1024`, `4096`, `8192` bytes). Uses a custom iterator (`iter_custom`) to measure wall-clock time for a batch of publishes followed by a single `flush`, providing accurate end-to-end latency including server acknowledgment.
- **`criterion_group!` / `criterion_main!`** — Criterion macros that wire up the `benches` group as the binary entrypoint.

## Usage Example

Run the benchmark suite from the workspace root:

```bash
# Run all benchmarks
cargo bench --bench nats_bench

# Run with a specific filter
cargo bench --bench nats_bench -- "legacy nats: publish"

# Compare against a saved baseline
cargo bench --bench nats_bench -- --save-baseline main
cargo bench --bench nats_bench -- --baseline main
```

Results are written to `target/criterion/` as HTML reports.

## Notes

- Requires a running test server, started automatically via the `nats_server::run_basic_server()` helper.
- Throughput is reported in **elements per second** (one message = one element). The bytes-based throughput alternative is commented out pending Criterion API clarification.
- Each message payload is pre-allocated as a slice of a 32 KB buffer filled with the byte value `22`, avoiding allocation overhead inside the hot loop.
