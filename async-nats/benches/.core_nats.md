Criterion benchmark suite for measuring core NATS client performance across publish, subscribe, and request-reply patterns at varying message sizes.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `publish` | `fn` | Benchmarks message publishing throughput (bytes/sec) and message rate (msgs/sec) at 32, 1024, and 8192 byte payloads |
| `subscribe` | `fn` | Benchmarks message consumption rate using a dedicated publisher task flooding the `bench` subject |
| `request` | `fn` | Benchmarks request-reply round-trip throughput with a responder task echoing replies |
| `publish_messages` | `async fn` | Inner loop helper: fires `amount` publishes to `"bench"` |
| `subscribe_messages` | `async fn` | Inner loop helper: drains `amount` messages from a `"bench"` subscription |
| `requests` | `async fn` | Inner loop helper: sends `amount` sequential request-reply calls |
| `core_nats` | `criterion_group!` | Registers `publish`, `subscribe`, and `request` into a single Criterion group |

## Usage Example

```bash
# Run all core NATS benchmarks
cargo bench --bench core_nats

# Run only the publish benchmarks
cargo bench --bench core_nats -- nats::publish

# Run with a specific message size filter
cargo bench --bench core_nats -- nats::publish_throughput/1024
```

```rust
// Benchmark parameters at a glance
// MSG sizes tested: 32 B, 1 KiB, 8 KiB (sliced from a 32 KiB static buffer)
// Messages per iteration:
//   publish/subscribe: 500_000
//   request:           10_000 (round-trips are ~50x more expensive)
```

## Notes

- Each benchmark spins up a real NATS server via `nats_server::run_basic_server()` and uses a live `async_nats` client, so results reflect actual network stack overhead.
- Sample size is set to `10` for all groups to keep wall-clock time reasonable; warm-up is 1 second.
- Source: [`async-nats/benches/core_nats.rs`](https://github.com/flamingo-stack/nats.rs/blob/main/async-nats/benches/core_nats.rs)
