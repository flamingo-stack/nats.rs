Integration tests validating TLS connectivity scenarios for the `async_nats` client, covering certificate loading, mutual TLS, TLS-first handshake, and native certificate store usage.

## Key Components

| Test | Description |
|------|-------------|
| `basic_tls` | Verifies mTLS with explicit root CA, client cert/key, and user/password auth; confirms failure without certs or with raw IP |
| `ip_basic_tls` | Tests TLS connection via IP address using an IP SAN certificate |
| `unknown_server_ca` | Asserts connection failure when the server CA is not trusted |
| `basic_tls_all_certs_one_file` | Validates loading root CA, client cert, and client key from a single bundled `.pem` file |
| `custom_tls_client` | Demonstrates supplying a custom `rustls::ClientConfig` with native root certs |
| `tls_with_native_certs` | Connects to `demo.nats.io` using the system's native certificate store |
| `tls_first` | Tests the TLS-first handshake mode (server speaks TLS before the NATS INFO handshake) and confirms standard mode fails |
| `tls_auto` | Validates that a server configured for `tls_first_auto` accepts both standard TLS and TLS-first clients |

## Usage Example

```rust
// Connect with mutual TLS using explicit certificates
let path = PathBuf::from(env!("CARGO_MANIFEST_DIR"));

let client = async_nats::ConnectOptions::with_user_and_password(
    "derek".into(),
    "porkchop".into(),
)
.add_root_certificates(path.join("tests/configs/certs/rootCA.pem"))
.add_client_certificate(
    path.join("tests/configs/certs/client-cert.pem"),
    path.join("tests/configs/certs/client-key.pem"),
)
.require_tls(true)
.connect("tls://localhost:4222")
.await
.unwrap();

// TLS-first handshake (server negotiates TLS before NATS INFO)
let client = async_nats::ConnectOptions::new()
    .require_tls(true)
    .tls_first()
    .connect("tls://localhost:9090")
    .await
    .unwrap();
```
