Integration tests validating JWT-based authentication flows for the `async_nats` client, including credential file loading, builder-pattern configuration, and reconnection behavior across multiple servers.

## Key Components

| Test | Description |
|------|-------------|
| `jwt_auth` | Connects using `ConnectOptions::with_credentials_file` and verifies a basic publish succeeds |
| `jwt_auth_builder` | Same as above but uses the builder-style `.credentials_file()` method on `ConnectOptions::new()` |
| `jwt_reconnect` | Spins up three JWT-protected servers, subscribes to a subject, then drops servers one-by-one to verify the client reconnects and message delivery continues |

## Usage Example

```rust
use std::path::PathBuf;

// Direct credentials file loading
let nc = async_nats::ConnectOptions::with_credentials_file(
    PathBuf::from("tests/configs/TestUser.creds"),
)
.await?
.connect("nats://localhost:4222")
.await?;

// Builder-style (equivalent)
let nc = async_nats::ConnectOptions::new()
    .credentials_file(PathBuf::from("tests/configs/TestUser.creds"))
    .await?
    .connect("nats://localhost:4222")
    .await?;

nc.publish("hello", "world".into()).await?;
```

## Notes

- Tests require a running NATS server configured with `tests/configs/jwt.conf` and a matching `TestUser.creds` file
- `jwt_reconnect` uses a 3-second sleep between server drops to allow reconnection to stabilize
- Server fixtures are managed via the `nats_server` test helper crate
