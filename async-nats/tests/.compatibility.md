Cross-language compatibility test suite for NATS JetStream object store operations, gated behind the `compatibility_tests` feature flag. It listens on NATS subjects to receive test commands from an external test harness and executes the corresponding object store operations.

## Key Components

- **`Test`** — Parses incoming NATS message subjects (`tests.<suite>.<test>`) into suite/test name pairs.
- **`ObjectStore`** — Implements individual object store compatibility test cases against a live NATS server.
- **`PinnedSubscriber`** — Type alias for a pinned, peekable `async_nats::Subscriber` stream used to consume sequential test commands.
- **`object_store()` test** — Entry point that subscribes to `tests.object-store.>`, dispatches to the appropriate test handler, and exits on `tests.done`.
- **`kv()` test** — Placeholder for a key-value compatibility suite (not yet implemented).

### Supported Object Store Test Cases

| Test Name | Description |
|---|---|
| `default-bucket` | Creates a bucket with default config |
| `custom-bucket` | Creates a bucket with provided config |
| `put-object` | Downloads a URL and stores it in a bucket |
| `get-object` | Retrieves an object and replies with its SHA-256 digest |
| `put-link` | Creates a named link to an existing object |
| `get-link` | Retrieves a linked object and replies with its SHA-256 digest |
| `update-metadata` | Updates object metadata |
| `watch` / `watch-updates` | Watches a bucket for changes |

## Usage Example

Enable the feature flag and point at a running NATS server before running:

```bash
# Start a NATS server with JetStream
nats-server -js

# Run compatibility tests against a remote harness
NATS_URL=nats://localhost:4222 cargo test --features compatibility_tests
```

```rust
// Tests are driven externally via NATS subjects:
// tests.object-store.get-object  → triggers get_object handler
// tests.done                     → signals test suite completion
```

> **Note:** These tests require an external test harness to publish commands on `tests.object-store.>` subjects. They are not standalone unit tests. See the [repository](https://github.com/flamingo-stack/nats.rs) for harness setup instructions.
