Integration tests for the `async_nats` WebSocket transport layer, verifying core pub/sub, large message handling, request/reply patterns, and TLS connections over WebSocket.

## Key Components

| Test | Description |
|------|-------------|
| `core` | Validates basic pub/sub, 1 MiB large message delivery (×10), and request/reply over plain WebSocket (`ws://`) |
| `tls` | Validates authenticated pub/sub over a TLS-secured WebSocket (`wss://`) with a custom root CA and user/password credentials |

Both tests are gated behind the `websockets` Cargo feature flag.

## Usage Example

Run the WebSocket integration tests with the feature flag enabled:

```bash
cargo test --features websockets --test websocket_test
```

To run a specific test:

```bash
cargo test --features websockets core
cargo test --features websockets tls
```

The tests depend on a running NATS server loaded from config files under `tests/configs/`:

```text
tests/configs/
├── ws.conf         # Plain WebSocket server on :8444
├── ws_tls.conf     # TLS WebSocket server on :8445
└── certs/
    └── rootCA.pem  # Root CA for TLS verification
```

Connecting via plain WebSocket and TLS in application code mirrors the test patterns:

```rust
// Plain WebSocket
let client = async_nats::ConnectOptions::new()
    .connect("ws://localhost:8444")
    .await?;

// TLS WebSocket with credentials
let client = async_nats::ConnectOptions::new()
    .user_and_password("derek".into(), "porkchop".into())
    .add_root_certificates("path/to/rootCA.pem".into())
    .connect("wss://localhost:8445")
    .await?;
```
