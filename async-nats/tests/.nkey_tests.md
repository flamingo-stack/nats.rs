Integration tests validating NKey-based authentication for the `async_nats` client, covering initial connection, builder-pattern configuration, and reconnection across multiple servers.

## Key Components

| Test | Description |
|---|---|
| `nkey_auth` | Verifies connection using `ConnectOptions::with_nkey` static constructor with a secret seed |
| `nkey_auth_builder` | Verifies the same flow via the `ConnectOptions::new().nkey()` builder pattern |
| `nkey_reconnect` | Stress-tests NKey auth across three servers, sequentially dropping each and asserting the client transparently reconnects |

## Usage Example

```rust
// Static constructor pattern
let nc = async_nats::ConnectOptions::with_nkey(SECRET_SEED.into())
    .connect(server_url)
    .await?;

// Builder pattern (equivalent)
let nc = async_nats::ConnectOptions::new()
    .nkey(SECRET_SEED.into())
    .connect(server_url)
    .await?;

nc.publish("hello", "world".into()).await?;
```

The reconnect test spins up three independent NATS servers (all using `tests/configs/nkey.conf`), connects with a single `ConnectOptions`, and drops servers one at a time while asserting message delivery continues uninterrupted.

## Notes

- Requires a running NATS server configured with NKey authorization (`tests/configs/nkey.conf`)
- `SECRET_SEED` is a test-only NKey seed — never use in production
- Tests are async and depend on `tokio` and `futures_util`
- Source: [`tests/client/nkey_tests.rs`](https://github.com/flamingo-stack/nats.rs/blob/main/async-nats/tests/client/nkey_tests.rs)
