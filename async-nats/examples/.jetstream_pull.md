Brief description: Demonstrates how to use NATS JetStream with a pull consumer in Rust — creating a stream, publishing messages, and consuming them with explicit acknowledgement.

## Key Components

| Component | Description |
|---|---|
| `PullConsumer` | Durable pull-based consumer bound to the `EVENTS` stream |
| `jetstream::new(client)` | Creates a JetStream context for stream/consumer management |
| `create_stream` | Creates the `EVENTS` stream subscribing to `events.>` subjects |
| `create_consumer` | Creates a durable pull consumer named `"consumer"` |
| `consumer.messages()` | Returns an async message iterator, optimised for batched retrieval |
| `message.ack()` | Explicitly acknowledges each message to JetStream |

## Usage Example

```rust
// Connect and set up JetStream context
let client = async_nats::connect("nats://localhost:4222").await?;
let jetstream = jetstream::new(client);

// Create stream + durable pull consumer (chainable)
let consumer: PullConsumer = jetstream
    .create_stream(jetstream::stream::Config {
        name: "EVENTS".to_string(),
        subjects: vec!["events.>".into()],
        ..Default::default()
    })
    .await?
    .create_consumer(jetstream::consumer::pull::Config {
        durable_name: Some("consumer".into()),
        ..Default::default()
    })
    .await?;

// Consume up to 10 messages
let mut messages = consumer.messages().await?.take(10);
while let Some(message) = messages.next().await {
    let message = message?;
    message.ack().await?;
}
```

Override the server address via the `NATS_URL` environment variable (defaults to `nats://localhost:4222`).

## Notes

- **Double `await` on publish**: The first `.await?` sends the message; the second `.await?` waits for the JetStream publish acknowledgement. The second can be deferred or omitted to avoid blocking subsequent publishes.
- **`.take(10)`**: Limits the iterator to 10 messages; remove or adjust for production workloads.
