Demonstrates concurrent NATS subscriptions and publications across multiple Tokio tasks using cloned `async_nats::Client` instances.

## Key Components

| Component | Description |
|---|---|
| `client.clone()` | Clones the NATS client for use across multiple async tasks |
| `client.subscribe(subject)` | Creates a subscriber on `"foo"` and `"bar"` subjects |
| `client.publish(subject, payload)` | Publishes 10,000 messages to each subject concurrently |
| `futures_util::try_join!` | Awaits both publisher tasks in parallel and collects durations |

## Usage Example

```rust
use futures_util::stream::StreamExt;

#[tokio::main]
async fn main() -> Result<(), async_nats::Error> {
    let client = async_nats::connect("nats://localhost:4222").await?;

    // Subscribe on "foo" in a separate task using a cloned client
    tokio::task::spawn({
        let client = client.clone();
        async move {
            let mut subscriber = client.subscribe("foo").await?;
            while let Some(message) = subscriber.next().await {
                println!("Received: {message:?}");
            }
            Ok::<(), async_nats::Error>(())
        }
    });

    // Publish concurrently from another cloned client
    client.publish("foo", "data".into()).await?;
    Ok(())
}
```

## Notes

- `Client` is cheaply cloneable — each task should own its own clone rather than sharing a reference
- Subscriber tasks run indefinitely; the example relies on the publisher tasks completing to bound execution
- `futures_util::try_join!` short-circuits on the first `JoinError`, so task panics are surfaced immediately
