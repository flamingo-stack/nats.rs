Demonstrates how to use `async_nats` from synchronous Rust code by driving an async NATS client with a single-threaded Tokio runtime via `block_on`.

## Key Components

| Component | Description |
|---|---|
| `tokio::runtime::Builder::new_current_thread` | Creates a single-threaded Tokio runtime for blocking async calls |
| `rt.block_on(...)` | Bridges sync and async contexts by blocking the current thread until the future resolves |
| `subscription.take(10)` | Limits the subscription stream to 10 messages (sync-safe, no async context needed) |
| Async drop block | Ensures subscriptions and clients are dropped inside an async context to allow proper cleanup task spawning |

## Usage Example

```rust
fn main() -> Result<(), async_nats::Error> {
    // Build a single-threaded runtime
    let rt = tokio::runtime::Builder::new_current_thread()
        .enable_all()
        .build()?;

    // Connect, subscribe, and publish — all driven synchronously
    let client = rt.block_on(async_nats::connect("nats://localhost:4222"))?;
    let subscription = rt.block_on(client.subscribe("foo"))?;
    let mut subscription = subscription.take(10);

    for _ in 0..10 {
        rt.block_on(client.publish("foo", "Hello, sync code!".into()))?;
    }

    while let Some(msg) = rt.block_on(subscription.next()) {
        println!("Received: {msg:?}");
    }

    // Drop async resources inside an async block for clean shutdown
    rt.block_on(async {
        drop(subscription);
        drop(client);
    });

    Ok(())
}
```

> **Note:** Always drop NATS subscriptions and clients inside an async block (`rt.block_on(async { drop(...) })`). Subscriptions spawn background cleanup tasks that require an active async context to finalize correctly.
