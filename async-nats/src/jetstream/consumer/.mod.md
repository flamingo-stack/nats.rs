Provides the core Consumer API for NATS JetStream, defining shared types, traits, and configuration structures used by both push and pull consumer implementations.

## Key Components

- **`Consumer<T>`** — Generic consumer struct holding context, config, and cached server info. Parameterized over any type implementing `IntoConsumerConfig`.
- **`IntoConsumerConfig`** — Trait for converting a config type into the generic `Config`.
- **`FromConsumer`** — Trait for converting a generic `Config` into push- or pull-specific configs with validation.
- **`Config`** — Full consumer configuration struct covering delivery policy, ack policy, durability, filtering, and more.
- **`Info`** — Server-side consumer info including delivery stats, cluster info, and (with `server_2_11`) pause state.
- **`SequenceInfo`** — Tracks consumer and stream sequence progress with optional last-active timestamp.
- **Type aliases** — `PullConsumer`, `PushConsumer`, `OrderedPullConsumer`, `OrderedPushConsumer` for ergonomic usage.
- **Submodules** — `pull` and `push` submodules containing consumer-specific configs and message handling.

## Usage Example

```rust
use async_nats::jetstream::consumer::PullConsumer;

#[tokio::main]
async fn main() -> Result<(), async_nats::Error> {
    let client = async_nats::connect("localhost:4222").await?;
    let jetstream = async_nats::jetstream::new(client);

    // Retrieve a pull consumer and inspect its info
    let mut consumer: PullConsumer = jetstream
        .get_stream("events")
        .await?
        .get_consumer("my-consumer")
        .await?;

    // Fetch fresh info from the server (updates cache)
    let info = consumer.info().await?;
    println!("Pending messages: {}", info.num_pending);

    // Read from local cache without a server round-trip
    let cached = consumer.cached_info();
    println!("Consumer name: {}", cached.name);

    Ok(())
}
```
