Cloneable handle to a NATS connection, providing async publish, subscribe, and request-reply messaging operations over a Tokio-based channel.

## Key Components

| Component | Description |
|---|---|
| `Client` | Core struct — cloneable handle wrapping an async channel sender, server info watcher, and connection state |
| `PublishError` / `PublishErrorKind` | Typed error for publish operations (`MaxPayloadExceeded`, `BadSubject`, `Send`) |
| `traits::Publisher` | Trait for publishing messages with reply subjects |
| `traits::Subscriber` | Trait for creating subject subscriptions |
| `traits::Requester` | Trait for sending request-reply messages |
| `traits::TimeoutProvider` | Trait for exposing the configured request timeout |
| `Sink<PublishMessage>` impl | Enables backpressure-aware streaming of publish messages via `PollSender` |

## Usage Example

```rust
use async_nats;
use std::str::FromStr;

#[tokio::main]
async fn main() -> Result<(), async_nats::Error> {
    let client = async_nats::connect("demo.nats.io").await?;

    // Basic publish
    client.publish("events.data", "payload".into()).await?;

    // Publish with headers
    let mut headers = async_nats::HeaderMap::new();
    headers.insert("X-Header", async_nats::HeaderValue::from_str("Value").unwrap());
    client.publish_with_headers("events.data", headers, "payload".into()).await?;

    // Check server version compatibility
    assert!(client.is_server_compatible(2, 8, 4));

    // Inspect server info and request timeout
    println!("server: {:?}", client.server_info());
    println!("timeout: {:?}", client.timeout());

    Ok(())
}
```

`Client` is cheaply cloneable via `Arc`-backed internals and is safe to share across tasks. Instances should be created via [`async_nats::connect`](https://github.com/flamingo-stack/nats.rs/blob/main/src/lib.rs) or [`ConnectOptions::connect`](https://github.com/flamingo-stack/nats.rs/blob/main/src/options.rs) rather than constructed directly.
