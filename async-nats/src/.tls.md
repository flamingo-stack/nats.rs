TLS configuration utilities for establishing secure NATS client connections using `tokio-rustls` and `rustls`.

## Key Components

| Function | Description |
|---|---|
| `load_certs` | Async loader for PEM-encoded certificates; returns empty vec if no certs found |
| `load_key` | Async loader for a PEM-encoded private key; errors if no key is present |
| `config_tls` | Builds a `rustls::ClientConfig` from [`ConnectorOptions`](https://github.com/flamingo-stack/nats.rs/blob/main/src/connector.rs), merging native system certs, user-provided CA certificates, and optional mTLS client credentials |

## Behavior Notes

- **System certs** are loaded automatically via `rustls-native-certs` unless a pre-built `tls_client_config` is supplied or user CA certificates are explicitly provided.
- **mTLS** is enabled when both `client_cert` and `client_key` are set in `ConnectorOptions`; supplying a cert without a key returns an error.
- **Pre-built config** (`tls_client_config`) short-circuits all certificate loading logic and is used as-is.

## Usage Example

```rust
use crate::connector::ConnectorOptions;
use crate::tls::{config_tls, load_certs, load_key};
use std::path::PathBuf;

// Load individual PEM components
let certs = load_certs(PathBuf::from("client.pem")).await?;
let key   = load_key(PathBuf::from("client.key")).await?;

// Build a ClientConfig from ConnectorOptions
let options = ConnectorOptions {
    certificates: vec![PathBuf::from("ca.pem")],
    client_cert:  Some(PathBuf::from("client.pem")),
    client_key:   Some(PathBuf::from("client.key")),
    ..Default::default()
};

let tls_config = config_tls(&options).await?;
// Pass tls_config to the NATS connector
```
