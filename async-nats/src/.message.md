Represents a Core NATS message transmitted over a NATS connection, encapsulating all message metadata and payload.

## Key Components

### `Message` (struct)

The primary message type for Core NATS pub/sub and request-reply patterns.

| Field | Type | Description |
|---|---|---|
| `subject` | `Subject` | The topic this message is published to |
| `reply` | `Option<Subject>` | Optional reply subject for request-reply patterns |
| `payload` | `Bytes` | Raw message body (arbitrary format) |
| `headers` | `Option<HeaderMap>` | Optional key-value message headers |
| `status` | `Option<StatusCode>` | Optional status code for internal handling |
| `description` | `Option<String>` | Optional description for the status field |
| `length` | `usize` | Total byte length of the message |

The struct derives `Clone`, `Debug`, `Serialize`, and `Deserialize` for full serde compatibility.

## Usage Example

```rust
use bytes::Bytes;
use nats::Message;

// Construct a basic message
let msg = Message {
    subject: "events.user.created".parse().unwrap(),
    reply: Some("_INBOX.abc123".parse().unwrap()),
    payload: Bytes::from(r#"{"id": 42}"#),
    headers: None,
    status: None,
    description: None,
    length: 10,
};

// Access fields after receiving from a subscriber
if let Some(reply_to) = &msg.reply {
    println!("Reply on: {}", reply_to);
}
println!("Payload: {:?}", msg.payload);
```

## Notes

- The `reply` field enables the request-reply pattern via `Client::request`.
- `status` and `description` are primarily used for NATS protocol-level status messages (e.g., `404 No Responders`), not application logic.
