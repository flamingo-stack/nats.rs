Provides a low-level NATS protocol connection implementation, handling framed reading and writing of NATS server operations (PING, PONG, MSG, HMSG, INFO, ERR) over async TCP or WebSocket streams.

## Key Components

- **`State`** — Enum representing connection lifecycle states: `Pending`, `Connected`, `Disconnected`.
- **`ShouldFlush`** — Enum signaling whether the write buffer needs flushing (`Yes`, `May`, `No`).
- **`AsyncReadWrite`** — Supertrait combining `AsyncRead + AsyncWrite + Send + Unpin`, enabling trait objects for both TLS and plain TCP streams.
- **`Connection`** — Core struct wrapping the async stream with read/write buffers and write-coalescing logic. Key methods:
  - `new()` — Constructs a connection with a configured read buffer capacity and statistics tracker.
  - `try_read_op()` — Attempts to parse a complete `ServerOp` from the read buffer (returns `None` if more data is needed).
  - `is_write_buf_full()` — Checks if the soft write buffer limit (`65535` bytes) has been reached.
  - `should_flush()` — Returns a `ShouldFlush` hint to drive back-pressure and flush scheduling.

## Usage Example

```rust
use std::sync::Arc;
use crate::connection::Connection;
use crate::Statistics;

// Wrap a stream (e.g., TcpStream) and create a connection
let stream = Box::new(tcp_stream);
let stats = Arc::new(Statistics::default());
let mut conn = Connection::new(stream, 65535, stats);

// Poll for incoming server operations
match conn.try_read_op()? {
    Some(ServerOp::Ping) => println!("Received PING"),
    Some(ServerOp::Message { subject, payload, .. }) => {
        println!("Message on {subject}: {payload:?}");
    }
    None => println!("Waiting for more data..."),
    _ => {}
}

// Check flush state before writing
match conn.should_flush() {
    ShouldFlush::Yes => { /* flush immediately */ }
    ShouldFlush::May => { /* flush if idle */ }
    ShouldFlush::No  => { /* skip flush */ }
}
```
